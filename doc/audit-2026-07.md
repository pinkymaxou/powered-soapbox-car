# Firmware audit — July 2026

Requested after the ADS1115 incident: find the other flaws of the same families —
peripherals able to stall the 500 Hz loop, failure modes that return valid-looking
values, and fixed buffers whose guards don't actually guard. Every `.cpp/.hpp` under
`firmware/main/` was read end to end; everything reachable from the control task was
traced (I2C, mutexes, NVS, logging), every sensor-failure return path checked for
sentinel values, every static buffer checked against the bound its guard claims.

## Fixed (commit of 2026-07-30)

| # | Flaw | Family |
|---|------|--------|
| 1 | **Recalibrating while armed left the kart drivable.** The wizard tells the driver to push both sticks to their stops — with the kart armed those sweeps were live full-throttle commands. `input::calibrated()` now reports false during collection (→ blocking NOCAL → disarm + brake, re-arming refused until the wizard ends) and `input::get()` zeroes the calibrated axes for the same window. | safety |
| 2 | **The blue "calibration" LED was dead code.** `State::Calibrate` exists in the enum but nothing ever produced it. The strip now derives blue directly from `input::calState()`, and it outranks the red fault blink that fix #1 deliberately raises during collection. | silent failure |
| 3 | **The history guard checked the wrong buffer.** `HIST_PB_MAX` was static-asserted against the 10 240-byte reply arena, but Hist encodes into its own 1 024-byte cache — a guard that could never fire, in front of an encode that fails silently (charts just stop). Now asserted against `HIST_BIN_CAP`. | guard mismatch |
| 4 | **Two readers stole each other's loop-time peaks.** `loopMaxUs()` is reset-on-read and had two consumers (the 5 s history slots and the System-tab poll): with the System tab open the worst-tick chart under-reported. One peak slot per consumer. | measurement lies |
| 5 | **`wifiset` wrote NVS while armed.** A flash write suspends the cache and freezes the control loop for tens of ms; the `set` path defers to the disarm edge but the Wi-Fi path didn't. Now refused while armed, through the existing error channel. | loop stall |
| 6 | **Oversized WebSocket frame desynced the socket.** A frame > 1 024 B was "handled" by returning OK with the payload left unread — httpd then parsed those bytes as the next frame header. Now the socket is closed (verified live: client reconnects clean). | protocol |
| 7 | **Low-battery orange lied when the voltage was unknown.** Telemetry reports 0 V while the ADS1115 is silent, which is below every warn threshold — the strip claimed "low battery" when the truth was "no reading". Gated on `vbat > 0`. | sentinel value |
| 8 | **IPv6 array sized by hope.** `esp_netif_get_all_ip6` fills up to `LWIP_IPV6_NUM_ADDRESSES` entries with no cap parameter; the buffer was a hard-coded `[5]` over a config of 3 — a silent stack overflow the day the sdkconfig is raised. Sized by the config macro. | unbounded buffer |

Plus a stale comment in `ads1115.cpp` that still said the shared I2C timeout was 4 ms.

## Checked and accepted as-is

- **`configFlushPending()` runs in the control task** on the armed→disarmed edge. A flash
  write freezes every flash-resident task regardless of which one issues it, so moving it
  buys nothing; it only ever runs disarmed, braking is latched in LEDC hardware, and the
  median-of-5 speed filter absorbs the one aliased encoder delta. Same reasoning covers
  `configUpdate` persisting immediately when disarmed while holding the config mutex.
- **Telemetry `vbat` is 0.0 (not −1) while unknown.** The page and the LED strip both gate
  on the NO_VBAT bit / `vbat > 0`, so nothing downstream mistakes it for a reading anymore;
  the battery history dropping to 0 during an outage is visible rather than misleading.
- **Torn string reads** (`m_name`, `m_sta_ip`): written by one task, read by another with no
  lock. Worst case is one garbled *display* string for one frame; both are bounded and
  null-terminated. Not worth a mutex on the status path.
- **Stuck-wheel detection is blind during a pure pivot** (mean of the two outputs ≈ 0). By
  design: the per-wheel reversal and aberrant-speed checks stay armed and cover it.
- **`reboot` is honored while armed.** It is an explicit human action, equivalent to the
  power switch, and the motor pins fall back to dynamic braking through the external
  pull-downs (see README on reset behaviour). Refusing it would remove a legitimate remote
  kill while adding no safety.
- **Worst observed tick on the bench is 2.4–9.5 ms against the 2 ms budget** with one
  encoder unplugged (wall clock, includes Wi-Fi/BT preemption; I2C cost alone 1.7–3.4 ms).
  The aliasing ceiling is 94 ms, so the margin is ×10 even at the worst peak; the loop
  chart on the Dashboard now makes any drift visible.
- **`heap_min` reads ~5.5 kB** after boot (Wi-Fi + BT + httpd init transient). A 9.5-minute
  two-client WebSocket soak holds `heap_free` stable at ~19 kB with zero errors — no leak —
  but new features that allocate at runtime should re-run that soak and watch this number.
